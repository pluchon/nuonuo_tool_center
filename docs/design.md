# 诺诺的图床：设计文档

> 状态（2026-11-21）：本地功能（P0）已完成并在用；AI 阶段方案已定稿，按第 9 节的顺序开工。界面以 [`prototype/`](prototype/) 的应用原型为准，文字规则写在这里，两者冲突时问用户。标【已核实】的有文档或实测依据，标【待验证】的开工时先测。

## 1. 目标与原则

只给自己用的 Windows 桌面软件：导入几个图片目录（二次元图、表情包、照片），管理、打标签、搜索；AI（诺诺）在后台帮忙认图、起名、打标签，在对话里帮忙找图。

- 本地优先：能在本地做完的不调大模型；调大模型就要省，要命中缓存（见 6.8）。
- 原目录允许改动（移动、改名、删除）。删除一律进系统回收站，应用里不另设回收站和操作记录页面。
- R-18 图永远不上云、不进云端检索和记忆；本地检索照常能搜到（见 5.9、6.7）。
- 云端只接阿里百炼，凭证只从用户环境变量读取（`DASHSCOPE_API_KEY`、`ALIYUN_ACCESS_KEY_ID`、`ALIYUN_ACCESS_KEY_SECRET`），不进代码、不进库、不写日志。
- 界面上不写解释性的小字：状态提示只有标题和操作按钮；能用数字和状态表达的不用句子。

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | Electron 45 + TypeScript，electron-vite 构建 | 不打包，桌面快捷方式直接跑 `out/` |
| 界面 | Vue 3 + Pinia + Element Plus（只按需引入树和消息提示） | 组件拆成 `.vue/.ts/.scss`；页面只经 `src/api/` 调用，状态只经 action 修改 |
| 数据库 | PGlite 0.5（内嵌 PostgreSQL）+ pgvector | SQL 只写标准 PG 语法；没有 pg_trgm，模糊搜索用 `ILIKE` |
| ORM / 迁移 | Drizzle ORM，迁移只往前加 | 改 `schema.ts` 后 `npm run db:generate` |
| 图片处理 | sharp | 缩略图、上传前缩图、去 EXIF |
| 本地推理 | onnxruntime-node，只跑 WD tagger 做 R-18 初判 | 只用 CPU，3–4 线程【已核实：原版 2 线程约 1 秒一张；int8 量化版 2/3/4 线程约 0.54/0.44/0.39 秒一张】 |
| 云端 | 百炼（OpenAI 兼容端点）+ 阿里云 OSS | 见 6.9 |

全项目只有 TypeScript，不需要 Python。

## 3. 进程与分层

```
渲染进程 (Vue)
  views → stores(actions) → src/api/*  ──IPC──┐
                                             │  preload：只暴露带类型的 window.api
主进程                                        ▼
  ipc/*（参数校验、调用）→ services/*（业务、事务、状态流转）→ repositories/*（Drizzle）→ PGlite
  ├─ services/scan        扫描、缩略图、实时监听
  ├─ services/fileOps     唯一允许写文件系统的地方，操作串行排队，先写日志再动文件
  ├─ services/rating      WD 分级（调度在主进程，推理在 workers/ratingWorker 的 utilityProcess 里，不卡主进程）
  ├─ services/cloud       OSS 临时上传、百炼调用、用量记账
  └─ services/ai          诺诺：harness、找图、看图队列、记忆与做梦（第 6 节，待建）
自定义协议 ltm://thumb/{hash}、ltm://file/{fileId}、ltm://bg/{name}
  图片走协议直接加载，不经 IPC 传 base64；只给图库里登记过的文件，不接受路径（防穿越）
```

安全设置：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`，CSP 含 `font-src 'self' data:`（打包时小字体文件被内联成 data:）。

## 4. 数据与目录

### 4.1 数据目录与运行

- 数据目录由 `LTM_DATA_DIR` 决定（数据库 `pgdata`、缩略图、模型、日志、锁文件、`window-state.json`、自定义背景）；不设时（桌面快捷方式）固定为 `%APPDATA%\LocalToolManage`，不随 productName 变。类目录所在的图库文件夹由 `LTM_CATEGORY_HOME` 或设置决定，默认 `D:\诺诺图床\`。
- 开发用 `D:\ltm-dev\data` 和 `D:\ltm-dev\library`，端到端测试用 `D:\ltm-dev\e2e\<场景>`；开发和测试不碰真实目录。
- 同一个数据目录只允许一个进程：单实例锁按数据目录区分，另用应用自己的锁文件 `ltm.lock`（记真实 PID 和进程名）判断“图库数据被占用”，不看 PGlite 的 `postmaster.pid`。
- 关闭走正常退出，保证数据库落盘、释放锁。
- WD 模型（onnx，约 450 MB）首次需要时下载到数据目录，不进仓库。

### 4.2 数据模型

所有业务表都有 `id BIGINT GENERATED ALWAYS AS IDENTITY`、`create_time`、`update_time`、`delete_state`，默认逻辑删除；状态一律用枚举。几千张图的规模，向量直接暴力算相似度，不建 HNSW。

| 表 | 作用 | 关键字段 / 约束 |
|---|---|---|
| `library_root` | 图库目录 | `kind`（SOURCE 源目录 / CATEGORY 图库文件夹，后者只有一条）、`path`（不区分大小写唯一）、`name`、`last_scan_at` |
| `image` | 按内容去重的图片，名字和标签挂在这里 | `content_hash`（sha256 唯一）、宽高、格式、`display_name`、`description`、`is_r18`、`rating`、`rating_source`（MODEL / MANUAL）、`rating_scores`、`taken_at`、`exif`、`thumb_ready` |
| `image_file` | 图片在磁盘上的位置（同一内容可有多处） | `image_id`、`root_id`、`rel_path`（未删除记录内唯一）、`status`（NORMAL / MISSING / DELETED） |
| `tag_category` / `tag` / `tag_alias` | 标签分类、标签字典、别名 | 名字和别名都不区分大小写唯一；还有标签在用的分类不能删 |
| `image_tag` | 图片和标签 | `source`（MANUAL / VLM）、`status`（ACCEPTED / SUGGESTED / REJECTED） |
| `file_op_batch` / `file_op` | 文件操作日志，只用于崩溃对账 | `origin`（USER / AI）、批次 PLANNED → APPLYING → APPLIED / UNDONE / FAILED |
| `app_setting` | 设置 | key/value，不存密钥 |
| `image_ai_result` | AI 给的建议（原样存 JSON） | 来源（诺诺看图 / 外部 AI）、各字段采用状态、`model`、`usage` |
| `image_embedding` | 语义向量 | `image_id`、`model`、`embedding vector(1024)` |
| `api_usage` | 每次云端调用记账 | 调用类型、输入 / 命中缓存 / 写入缓存 / 图片 / 输出 token、联网搜索次数、是否批量、耗时、失败原因 |
| `ai_conversation` / `ai_message` | 对话 | 标题、置顶、锁定的档案版本；消息的赞 / 踩 |
| `ai_event` | 事件流（只追加，不回写） | 类型、相关图片、内容 JSON、是否涉及 R-18；做梦整理到哪一条记在 `ai_job` 的 payload 里 |
| `ai_memory` | 事实记忆 | 内容、类型、向量、可信度、生效时间、失效时间、来源消息或事件 |
| `ai_profile` | 核心档案（带版本） | 正文（500 字以内）、标签词表快照、版本号（唯一） |
| `ai_job` | 后台任务（看图、做梦、补向量） | 类型、状态、优先级、批量任务 id、尝试次数、开始和结束时间 |

所有表都已建好（迁移 `0003_ai_foundation`），AI 的表还没有界面在用。

## 5. 本地功能（已完成）

### 5.1 导入、扫描与监听

- 导入源目录：点侧栏“源目录”的“+”、首页“选择图片文件夹”、或把文件夹拖进窗口，弹 Windows 自己的选文件夹对话框。不能导入的文件夹（已导入的、它的上下层、应用自己的图库文件夹）由主进程校验，用红色提示条说原因。
- 格式：jpg / png / webp / gif / bmp / avif、heic / heif、相机 RAW（arw / cr2 / cr3 / nef / dng / raf / orf / rw2）；按设置可以不扫某些格式、跳过小图。读 EXIF（机身、镜头、焦距、光圈、快门、ISO、拍摄时间）。
- 扫描在主进程串行排队，同时处理 2–4 个文件（按核数），每个 sharp 只用 1 线程，进度按 150 ms 节流推给窗口。64 MB 以内的文件只读一次，同一份内容算哈希、解码、写缩略图；修改时间和大小都没变、缩略图已处理过的不重算。“停止扫描”处理完手上的文件就停。
- 对账：只有一次扫描完整结束、所有目录都处理完才对账。读不了的目录和文件、找不到的源目录、按设置不扫的文件都不动；同一内容在别处有正常位置的旧记录直接去掉，其余标 MISSING；文件放回来改回 NORMAL。外部删掉的文件从列表里去掉，名字和标签留在 `image` 上，放回来按哈希认回；被移动或改名的按哈希接回。
- 缩略图：webp，限制在 1000×400 以内，按 EXIF 方向转正；RAW 用最大的内嵌 JPEG；BMP 自己解未压缩的 24 / 32 位；解不了的（HEIC/HEVC、调色板 BMP 等）记为“无法预览”。走协议时先 stat 确认文件在再流式给，被删掉时马上 404；“已生成”但文件不在的缩略图在扫描时补回。
- 实时监听：Node 自带的 `fs.watch(目录, { recursive: true })`，每个源目录和图库文件夹一个。不用 chokidar（它在 Windows 上给每个子文件夹各开一个监听，文件夹就改不了名、删不掉）。应用自己改文件时和之后 2.5 秒内的变化不算外部变化；一个目录停 1.5 秒没有新变化就排进扫描队列；自动扫描不弹完成提示。监听的目录本身被删掉或移走时 Windows 会不停报带 `\\?\` 前缀的绝对路径，遇到就关掉这个监听、重扫一次，侧栏标“找不到”。
- 源目录找不到时“重新选择”只改路径，名字和相对路径不变，记录和标签都接上。
- 启动时自动扫描（可关），不弹完成提示（有读失败的除外）；底栏扫描时间只看源目录，旁边有“重新扫描”。

### 5.2 浏览与网格

- 侧栏：图库（全部图片、还没打标签、最近导入）、源目录、类目录、整理（标签管理、R-18 图）、AI（诺诺助手、AI 建议）。“全部图片”只显示打过标签的图，没标签的只在“还没打标签”里。
- 侧栏滚动：整个侧栏可滚动；目录分组的列表在框内自己滚，鼠标在分组上时只滚这个分组，滚到头不带着整个侧栏滚。
- 网格排版：按原比例排成行，所有行同一高度；行末用“整行略压窄”或“最后一张挪到下一行、整行略撑宽”中变形更小的一种对齐右边，最后一行不拉伸。长宽比限制在 0.5–2.5，超出的显示中间部分，左下角标“全景 / 长图”。右下角半透明格式标记，下方只放名字。很窄的长图上 R-18 角标只留锁图标、格式标记隐藏。
- Ctrl + 滚轮在 5 档行高之间切换（约每行 3 到 8 张），默认中间档（140px），存在本机。
- 按月分组：排序为最近 / 最早导入时按导入月份，拍摄时间排序时按拍摄月份（没有拍摄时间的归到最后），按大小、名称排序时不分组。组头跟着滚动、不吸顶：主题色渐变竖条 + “2026 年 11 月”粗体 + 一颗静止的小星星 + 虚线 + 选择本月的小圆圈 + “N 张”胶囊。
- 一个视图的图片由主进程一次查全、过滤、排序再给界面；界面不分页，屏幕外的行用 `content-visibility` 跳过，缩略图懒加载。行上下各留空间再用负外边距抵掉，悬停浮起时描边和投影不被裁掉。同一内容在当前视图有多个位置只出一张。名称排序和资源管理器一致（数字、英文在前，中文按拼音，数字按大小）。
- 网格右侧自绘滚动条：留 14px 窄边，滑块是主题色渐变，平时半透明，悬停、拖动、滚动时变粗变亮；可拖、可点轨道跳转，拖到或点到底会贴底；按月分组时在旁边浮出当前月份气泡。
- 筛选：
  - 全部图片、R-18 图、类目录：搜索（标签和名字）、标签、目录、更多（格式、方向、尺寸、文件大小、拍摄时间）、排序（最近导入 / 最早导入 / 拍摄时间 / 文件大小 / 名称）。标签、目录各最多 5 个，组内“或”、组间“与”。全部图片和 R-18 图的目录下拉只列顶层目录，选父目录包含子目录。
  - 源目录及其子文件夹、还没打标签、最近导入、AI 建议：只按图片名搜。“还没打标签”另有平铺的目录筛选（只列含未打标签图的目录，少于两个不显示）。
  - 有子目录的源目录、类目录：筛选行最右侧（竖线隔开）有“仅展示当前目录图片（不含子目录）”开关，默认关。
  - 选中的条件进上方的筛选标签（所在目录不作为标签）；没有任何条件时不显示右侧“N 张”。下拉限制可见行数（筛选 10 行），多了框内滚动。
  - 切换视图清掉搜索和开关，排序回到默认排序；列表刷新时保留还在列表里的选中。
- 列表空了（筛选没结果、AI 建议都处理完）时，右侧详情面板往右收起、网格变宽，有图了再展开并选中第一张。
- 拖拽：
  - 直接拖缩略图（多选时整组）到侧栏源目录（含子文件夹）上：松手是复制、按住 Ctrl 是移动，弹确认后和“复制到 / 移动到”走同一套。类目录不接收拖放。
  - 按住约 0.4 秒再拖：系统原生拖拽带出原文件（多选时整组，跟手的是第一张的缩略图），可以拖进 Telegram、资源管理器等别的软件（`webContents.startDrag`）。诺诺助手的结果图直接拖就是原生拖拽。原图打不开的不带。
  - Ctrl + C：单张把图片放进剪贴板（PNG）；多选时提示用“复制到…”。

### 5.3 详情与编辑

- 右侧详情面板从上到下：预览（近黑 `#141118` 衬底，点它打开大图，右下角删除）、AI 建议卡（只在“AI 建议”视图里，见 6.5）、名字、文件信息（文件名、尺寸、大小）、拍摄信息（有 EXIF 才显示）、标签、图片源路径（文件夹按钮在路径左边，同一个框里一条细分隔线）、R-18 开关、其他 AI 辅助整理（见 6.6）、底部“复制到… / 移动到…”，“最近导入”里底部还有导入时间。内容多时整体滚动，里面的块不被压扁；面板不显示滚动条。
- 名字：最多 15 个字，回车或失焦保存、Esc 放弃；没起过名字时留空，文件名作占位文字，不计字数；清空等于用回文件名。字数上限不在输入时截断（会打断输入法），超出时计数变红并禁止保存。
- 标签：每张图最多 5 个。输入时按名字和别名匹配已有标签，最多列 5 个（前缀匹配优先，其次按图片数），已在这张图上的不列；“+”右侧选分类，新标签默认进“主题”，选过别的分类后沿用；输入的是已有标签就沿用它的分类。标签名去首尾空格、多个空格合一，最多 15 个字。移除标签只删关联。
- 编辑后图片离开当前视图时（如在“R-18 图”里关掉 R-18、在“还没打标签”里加上标签），选中移到同一位置上的下一张。

### 5.4 多选与批量

- Ctrl 点击逐张加选、Shift 按当前顺序连选，Ctrl 点击已选中的取消这一张（剩一张回单选），普通点击回单选；缩略图右上角的勾选圈等于 Ctrl + 点击。一次最多 200 张，Ctrl + A 全选当前列表（最多 200 张）。
- 选中 2 张以上时右侧是批量面板：顶部“已选 N 张”和一个无底无边的垃圾桶（删除全部选中）；下面是共同标签（可一起移除）、一起加标签（满 5 个的跳过并提示）、全部标 / 取消 R-18、复制到 / 移动到。不放“取消选择”，Esc 或普通点击回单选。

### 5.5 大图

- 打开：网格双击、Enter、空格（快速预览，再按空格关），或点详情预览图；← / → 按网格顺序换图（首尾相接），Esc 或点遮罩关闭，关闭后网格停在最后看的那张。从诺诺助手里双击结果图打开时，左右只在那次的结果里切换。
- 弹窗随窗口变大（最宽 1180px）；舞台不分明暗都是近黑衬底，图片保持自己的颜色。标题旁显示“第几张 / 共几张”。上一张 / 下一张是白色半透明圆钮，平时 35%，鼠标进舞台 70%，指着才完全显出。
- 缩放：Ctrl + 滚轮以鼠标位置为中心（25%–400%，超大图放宽到原始大小），按钮以舞台中心为准；放大后按住左键拖动平移，缩回 100% 以下自动回中；双击在适应窗口和原始大小之间切换（图比窗口小时放到 200%）；`+ − 0 1` 缩放、适应、原始大小。100% 是“适应窗口”，小图不放大；旋转后按新的宽高重新适应。
- 换图时先垫缩略图，原图读完淡入，读完后预读前后两张。HEIC、RAW 只看缩略图并在舞台下方说明；原图读不到时退回缩略图；都没有时显示“无法预览”和“用默认程序打开”。R-18 图在大图里正常显示。

### 5.6 目录管理

- 源目录、类目录在侧栏都是可展开的树（细线连接父子），点箭头只展开收起，点名字进入；子目录来自磁盘，数量含更深的子目录。有子文件夹的用叠放的多文件夹图标，类目录是带爱心的版本。
- 右键菜单（贴在所点目录下方，带尖角，半透明磨砂底）：类目录“新建子目录 / 重命名 / 打开所在文件夹 / 删除”；源目录顶层“新建子文件夹 / 重新扫描 / 打开所属源目录 / 从图库移除”；源目录子文件夹只有新建和打开。新建只走右键菜单和类目录卡片标题的“+”。
- 新建：在对应位置出输入行，空着回车用默认名（未命名的类目录 / 未命名的子目录 / 新建文件夹），同级重名加编号；目录名最多 15 个字，不能含 Windows 不允许的字符；建好后进入新目录。
- 类目录改名：磁盘改名后下面所有记录的路径前缀跟着换（先写日志），和兄弟重名拒绝。删除类目录：整个文件夹进系统回收站，副本记录去掉，源目录里的原图不受影响。从图库移除源目录：只是不再管理，磁盘不动，以后重新导入按哈希认回。
- 扫描进行中不新建、改名、删除目录，也不移除源目录。

### 5.7 删除、移动、复制

- `fileOps` 串行执行，日志先写库再动文件；启动时（以及“重试”打开图库成功后）先补做上次没做完的批次，再自动扫描。永不覆盖：重名自动加编号 `名字 (2).jpg`。跨盘移动先复制、校验哈希再删原文件。
- 删除：入口是详情预览的垃圾桶、批量面板的垃圾桶、网格里 Delete；设置开了“删除前确认”先弹确认。在源目录、类目录里只删这个目录里的位置（按“仅当前目录”开关），其他视图删这张图的全部位置；目录找不到的位置不动。先在库里标 DELETED（马上从网格消失），6 秒后逐个 `shell.trashItem`，提示条上的“撤销”在这之前有效，退出应用时马上执行。删不掉的恢复正常并红色提示原因。
- 移动 / 复制：对话框分源目录、类目录、其他位置三组，前两组是 `el-tree` 懒加载的文件夹树，打开时展开到当前位置（复制时也展开到各副本），每组最多 5 行可见；移动单选、复制多选（最多 20 个目录）；单张时“当前位置”不能选，复制时“已有副本”的目录不能选。“其他位置”的“选择文件夹…”弹系统对话框：选在图库里就和上面一样；在图库外时复制等于导出一份（不登记），移动等于移出图库（名字和标签留着，60 秒内可撤销挪回）。批量复制时平铺进目标文件夹，不保留子目录结构。原图打不开、扫描进行中时不可用。
- 移动先用独占方式在目标处建空文件占位再挪过去；复制用排他复制，撞名就换下一个编号。完成后 60 秒内可撤销：移动的挪回原处（原处被占则不挪并提示），复制出来的放进回收站。
- 操作提示：从窗口顶部弹入，5 秒后消失，带“撤销”。失败时换成红色图标、不自动消失，点“知道了”关闭，例如“有 2 张没复制成功：D 盘空间不足”。
- 端到端测试设 `LTM_FAKE_TRASH_DIR`，删除改成挪进场景目录下的 trash。

### 5.8 标签管理

- 页面按分类卡片列出全部标签，顶栏只有搜索框、“管理分类”圆形按钮和“新建标签”。分类卡片标题后面是书签样式的标签数（分类色的淡色），右侧调色板按钮弹出一排 8 个经典色的小卡片（尖角指向按钮），手动换色允许撞色。
- 分类：预设角色、作品、画师、主题、地点、人物、器材、风格，12 色调色板；“标签分类”对话框可改名、新增（叫“新分类”，重名加编号，随机取没被占用的颜色）、删除（只对没有标签在用的分类开放，删不了时用提示条说原因）。分类名最多 6 个字。
- 右侧面板：改名、换分类、别名、合并都先在面板里改，点底部按钮一次提交，没有改动时不可点，换选别的标签时放弃。标签名、别名不能和别的标签的名字或别名重复（不区分大小写），别名最多 15 个字。合并进来（最多 5 个）：来源的图改挂到当前标签，来源的名字和别名变成当前标签的别名，来源删掉；并入其他标签反过来。同一张图原来有两个标签的只留一个。删除标签：从所有图上去掉，图片本身不动，确认框只有“删除标签「X」？”和“先不删 / 删除”。“N 张 ›”回到全部图片并选上这个标签的筛选。新建标签默认放进第一个分类。

### 5.9 R-18

- 一张图是否 R-18 由 `is_r18` 决定：你手动开关的永远优先（`rating_source = MANUAL`）；本地 WD 模型判为 R-18 的直接打上（`MODEL`），详情的 R-18 一行标“诺诺判的”，判错了关掉开关就行，不设单独的复核流程。
- 本地判定口径：questionable + explicit 分数之和 ≥ 0.5 才算（只标明显的）【已核实：用户确认安全的 100 张全部放行，随机 40 张拦下 3 张】。只用 CPU（3–4 线程，见下一条），扫描后在后台补判，不跑 DirectML。
- 怎么跑：WD 在单独的 utilityProcess（`workers/ratingWorker.ts`，进程优先级调低）里推理，输入是已经生成好的缩略图（所有格式都已解码成 webp，不再读原图）。启动后和每次扫描结束时开始一轮，扫描进行中让路，一次一张；只在应用开着时跑，判过的记在库里，下次启动不重判。顺序：你在详情里打开的还没分级的图插到最前面先判，其余最新导入的在前、老图在后台慢慢判；每判完一小批（20 张）就把新判完的图交给看图队列和一键整理，不等整轮判完（第一次全库 3700 张约 25 分钟，照苹果、Immich 的做法：慢只在第一次，而且不挡你用）。速度（2026-11-22 实测，Ryzen 7 8845H）：原版推理一张约 0.97 秒（2 线程），预处理只要 18 毫秒；一次喂多张不快、内存从 0.8 GB 涨到 2.3 GB，不用；原版 4 线程约 0.66 秒，6 线程也只到 0.62。线程：你在用软件时 3 线程；插着电且软件窗口不在前台、或整台电脑 1 分钟没人操作时 4 线程；回到软件立刻降回 3 线程，换线程要重新加载模型约 3 秒所以加线程前要稳定 1 分钟。int8 版 2/3/4 线程一张约 0.54/0.44/0.39 秒。试过静态 int8 量化（QDQ 和 QOperator 两种格式，50 张本地图校准），2/4 线程约 0.62/0.48 秒，比动态量化慢，不用。NPU（8845H 是第一代 XDNA，只支持 CNN 类 INT8，onnxruntime-node 也没有 NPU 后端）和核显（DirectML / WebGPU，曾整机卡死）都不用。底栏有“本地分级中”胶囊显示进度；空闲 2 分钟关掉工作进程（模型常驻约 0.8 GB）。判过的记 `rating`、`rating_scores`、`rating_source = MODEL`；判不了的（缩略图读不出、超时）记成 UNKNOWN，不反复重试。判出 R-18 时通知界面刷新侧栏计数和网格。
- 手动开关过的图记 `rating_source = MANUAL`，模型永远不改；模型写库时也只写还没有来源的图，和手动操作同时发生时手动的赢。本地分级上线前已有的 R-18 标记由迁移 0004 记成手动的。
- 模型（`wd-swinv2-tagger-v3` 的 `model.onnx` 和 `selected_tags.csv`）在数据目录的 `models` 下，缺了在后台自动下载：先 huggingface.co，不通换 hf-mirror.com；下到 `.part`，断了下次用 Range 接着下，下完改名。开发和端到端测试用 `LTM_MODEL_DIR` 共用 `D:\ltm-dev\models` 里的一份。
- int8 量化版：同目录下有 `model.int8.onnx`（至少 150 MB）就优先用它，没有就用原版，日志记“本地分级用 …”。它由 `scripts/quantize-model.py` 在本机生成（onnxruntime 动态量化，只量化 MatMul / Gemm 权重，约 175 MB，几秒钟），不联网、不上传。【已核实（2026-11-22，Ryzen 7 8845H，2 线程）：一张从约 1.10 秒降到约 0.56 秒；679 张本地图（原版判出 55 张 R-18）里 R-18 零漏判，只多判 1 张贴着门槛的（原版 0.482、int8 0.511），四档最高一项 97% 一致】。没选更轻的模型和两段式筛选：它们都会漏判 R-18。
- 开关：关着是普通输入框的底加中性开关（白底灰圆点），开着整行淡玫红、开关变红。
- “R-18 图”视图只列开了 R-18 的图；缩略图在所有视图里默认模糊（设置可关），选中后详情和大图正常显示。在这个视图里关掉开关，图就离开列表。
- R-18 图不上云、不进 AI 记忆和云端检索；本地关键词检索照常能搜到。

### 5.10 设置

- 入口是标题栏应用名右侧的齿轮，900×620 弹窗，当前页面留在背后；改动即时生效、没有保存按钮；弹窗自己的底接近不透明。左侧分类，右侧分组卡片，每行“名称 + 控件”，分组标题写具体功能，不重复分类名。
  - 外观：外观模式（浅色 / 深色 / 跟随系统）、主题色（6 色；所有原来的紫色都跟着走，标签分类色和 R-18 等语义色不跟）、背景（默认 / Halftone / Plotter / Paper / 自定义图片）、背景淡化、磨砂玻璃、组件透明度和模糊程度、按月份分组。
  - 常规：开机自动启动、关闭窗口时（退出 / 最小化到托盘）、删除前确认、R-18 缩略图模糊、默认排序。
  - 图库：启动时自动扫描、实时监听、扫描的格式、跳过小图、类目录保存的位置。
  - 数据与缓存：数据文件夹、缩略图缓存大小（清理只删已没有对应图片的缩略图）、导出备份（`诺诺图床备份-年月日-时分.tar.gz`，PGlite `dumpDataDir`，不含图片文件，同名不覆盖）。
  - 快捷键（只读列表）、关于（版本和更新按钮、图片总数；还没有在线更新渠道，转一圈后显示“暂未开放在线更新”）。
- 背景：默认只用主题色的淡染，左上角稍亮；Halftone / Plotter / Paper 移植自 Claude Code 官方 theme-examples 插件（Apache-2.0，署名写在 `theme/scenes.ts`，发布时在“关于”或许可证文件里保留），深色窗口用各自的深色版，背景是动态的，系统开了“减少动画”时静止，面板玻璃换成该背景的纸色；自定义背景缩到最长边 2560 转 webp 存进数据目录，经 `ltm://bg/` 读。
- 实现约定：滑块拖动时先在界面生效，停下 250 ms 再存库；其余控件点了就存，以主进程返回的设置为准。开机自动启动只在正式使用时改系统登记。托盘：点关闭时藏起窗口，单击托盘图标回来，右键“打开 / 退出”。类目录位置有图时不换，不能和源目录、数据文件夹重叠，由环境变量指定时不可用。
- 窗口记住上次关闭时的位置、大小和是否最大化；屏幕变了看不见时居中打开。

## 6. AI：诺诺

### 6.1 原则

- 诺诺是一个轻量 harness：自己的对话循环、只读工具、记忆，跑在本机，只在需要时调云端。
- 本地优先，少调大模型；调用就要命中缓存（6.8）。目标：对话和批量任务按 token 汇总的缓存命中率不低于 95%。
- AI 只给建议，不直接改数据：名字、标签、角色、作品、出处都进“AI 建议”由你确认；整理文件只生成计划，你确认后才经 `fileOps` 执行。唯一例外是本地模型判 R-18（5.9）。
- 记忆完全在后台，用户层感知不到，界面里没有记忆的页面和开关。
- R-18 图不上云、不进记忆和云端检索。

### 6.2 界面

- 侧栏“AI”分组：诺诺助手（四角星图标）、AI 建议（有建议的图片数）。
- 底栏左侧只有一个“诺诺在看图”胶囊：渐变四角星（排队时按节奏转动）+ 数量。点开是带尖角的卡片：标题右侧“全部取消”；列表区高度固定，一次显示四行、多的滚动；看图中的那张写“看图中”（流光），其他写“等待中…”，出错的在名字后面挂轻量小标签（超时、读不到原图）并有重试按钮；看完的不在列表里；空了时卡片大小不变，中间放诺诺空状态插画。
- 胶囊右边依次是“一键整理”按钮（见 6.10）和“本地分级中”胶囊：盾牌图标、一根带流光的细进度条和“已判/这一轮要判的”，不能点开，判完就收起。
- 四角星动画：带阻尼的转动，先转半圈略冲过头再回弹停稳，停一拍再转下半圈，转时轻轻收一下，颜色缓慢变化，一圈约 2.8 秒；系统开了“减少动画”时不动。
- 诺诺助手页（完整对话页）：
  - 顶栏左边渐变星星和对话标题，右边“新对话”和“对话记录”。对话记录是带尖角的下拉：置顶的在前，其余按时间；今天只写时间，今年写“11月20日”，更早的加年份；右键可以重命名、置顶 / 取消置顶（标题右侧图钉，整行淡淡的深色底）、删除（可撤销）。
  - 新对话：诺诺插画、“想找什么图？说给诺诺听”和四个示例问题；示例从图库里非 R-18 图的角色、作品、地点、主题和目录随机拼，每开一次新对话换一批。
  - 消息：你的话在右边圆角浅色气泡；诺诺的回复不套气泡、没有头像，对话在中间限宽。回复依次是：一行灰色小字说明这次怎么找的（如“搜索了图库：标签「猫」，场景「秋天落叶」，找到 3 张”，不用“·”）、正文、结果图（名字是图片内部右上角的淡色小标签，R-18 角标在左上角）、底部一行“复制、点赞、踩、时间”。
  - 结果图：单击选中（主题色描边加对勾），选中后 Ctrl + C 复制，可以直接拖到别的软件（原生拖拽，带出原文件）；双击打开大图，大图里只在这次回复的结果之间切换。一次回复最多显示 12 张，普通图在前、R-18 图在后。
  - 等待回复时显示转动的星星和带流光的“诺诺在翻图库…”。
  - 输入框（参照 Gemini）：大圆角白底，占位“搜你所想...”；左下角“+”（往上弹出带尖角的菜单：上传图片 Ctrl + U、粘贴图片 Ctrl + V；选好的图在输入框上方显示小预览，可去掉；发出后显示在你的气泡里。【还没做：从图库里挑一张】）、目录选择（实心浅底圆角块，往上弹出：全部图库 / 源目录 / 类目录，可滚动）、竖线、“R-18 + 小开关”；右边发送键，有内容时主题色渐变，悬停时箭头往上走、循环。没有模型选择。
  - 对话里的系统提示用横幅，不当成诺诺说的话：如网络出错时一整行“——— (WiFi 断开图标) 网络异常 ———”，下面居中“重试”。没连上云端时整页只有诺诺出错插画、“诺诺还没连上云端”和“重试”。
- 弹出菜单在深色下比底下的面板亮一层、描边更清楚；叠在菜单上的右键菜单再亮一层。

### 6.3 harness

- 位置：主进程里的 `services/ai`，耗时的本地计算（WD、向量相似度）放 utilityProcess。
- 对话循环：qwen 的函数调用（OpenAI 兼容），每轮最多几步工具调用、单次超时、客户端 `maxRetries: 0`，失败在对话里显示横幅由用户重试。查询失败和“没有结果”分开报告，降级时不冒充语义判断。
- 工具（固定的一整套，顺序固定，用不用都带上）：
  - `search_images`：结构化条件（角色、作品、地点、标签、关键词、方向、最近导入、还没打标签）+ 一句语义描述（转成向量参与检索，见 6.7）。范围和是否含 R-18 不让模型传，按输入框里你的选择，模型改不了；
  - `get_image`：某张图的名字、文件名、尺寸、标签、描述（R-18 图只返回“是 R-18”）；
  - `list_tags`：按分类列标签和别名；
  - `remember`：记下你在对话里明说的偏好（不额外调模型，直接写 `ai_memory`，可信度 0.9）；
  - `propose_file_ops`：生成整理计划（PLANNED 批次），界面预览后你确认才执行【还没做：预览和确认界面没设计，加这个工具会让已有对话的缓存前缀失效一次】。
- 找图先走本地（6.7），本地能完整回答的不进对话循环。
- 一次回答最多 4 次模型调用（含工具往返），用完还在调工具就按最后一次检索给模板回复。工具往返不存库；下一轮当历史发给模型的是“你说的话”和“回复正文 + 给你看了哪些图（编号和名字，不含 R-18）”，历史只往后追加。
- 问和答分两步：先存下你说的话（新对话用问题前 14 个字当名字），再取回复；回复失败（网络、超时、云端拒绝）这句话留着，横幅上“重试”再取一次回复，不会重复存。

### 6.4 记忆与做梦

三层记忆，全部在本地 PGlite：

| 层 | 内容 | 用法 |
|---|---|---|
| 核心档案 `ai_profile` | 500 字以内的偏好摘要 + 标签词表快照，带版本 | 每次对话、每次看图、生成外部 AI 提示词时都带上 |
| 事实记忆 `ai_memory` | 一条条偏好和事实，带向量、可信度、生效和失效时间 | 按问题检索最相关的几条；旧的只标失效、不删 |
| 事件流 `ai_event` | 软件里的操作，只追加 | 做梦时整理的原料 |

- 事件流记的信号（权重从高到低）：对话里明说的偏好（经 `remember` 立刻写入，不等做梦）；你手动改名、加标签、复制或移动去了哪个目录、采用 AI 建议后又改成了什么；采用或拒绝了哪条建议；回复的赞和踩（最弱，只参考：踩不单独形成偏好，只降低相关记忆的可信度，赞只给已有偏好加一点分）。涉及 R-18 图的事件不进整理材料。
- 做梦（借鉴 Claude 的 dreaming 和 Letta 的 sleep-time compute）：
  - 只在空闲时做：几分钟没有操作，也没有扫描、看图、对话在跑。
  - 一旦有新任务就停：做梦拆成很多小步，每步开始前检查是否忙；已经发出的那一步请求跑完并保存（钱已经花了），不再开始下一步，本地的步骤立即停；下次空闲接着做。每步都可以重做，不会重复写入。
  - 步骤：先在本地把最近 3000 条事件汇总成统计（如“表情包移到表情包目录 12 次”“甘雨的名字被改成椰羊 3 次”），同一件事出现 3 次以上就用规则直接写成一条记忆（可信度随次数涨，重做不会重复写）；赞和踩只调整这次回复用到的记忆的可信度，低于 0.2 的标失效。只有把核心档案写成通顺的一段话才调模型（flash，实时调用：一天最多一次，批量要排几十分钟，省下的钱不值得多一套轮询）。
  - 实现：`dreamService` 在主进程里每分钟看一次，5 分钟没有操作（任何界面请求都算操作）且分级、看图、补向量、对话都不在跑时做一轮。
  - 核心档案最多一天更新一次；正在进行的对话锁定开始时的档案版本，新档案只在下一段对话生效（保证缓存前缀不变）。做梦上线前正文是空的，第 1 版在第一次开对话时建；标签词表（只含用在非 R-18 图上的标签，每个分类最多 80 个）变了且离上一版超过一天时出新版本。
- 记忆用在：对话的检索和语气；看图建议的名字和标签（按你的叫法、你常用的词，不再提你拒绝过的说法）；外部 AI 提示词里的“我的整理习惯”。

### 6.5 诺诺看图与 AI 建议

- 什么时候看：看图功能上线（`app_setting` 的 `ai.lookSince`）之后新导入、还没打标签、过了上云闸门的图，在本地分级判完后自动排进看图队列；之前就有的图不自动看，在详情“其他 AI 辅助整理”里点“让诺诺看看”单张排进去。平时逐张实时看（关掉思考后一张约 2–3k 输入 token、几秒，导入后很快就有建议）；一次排进 50 张以上（如第一次导入一个大目录）时，超出的部分每 100 张打成一个批量推理提交（半价，不联网搜索，要排几十分钟到几小时，每 5 分钟查一次结果）。
- 上云闸门：不是 R-18，并且是手动标过的，或者本地模型判为 general / sensitive。还没判完、判不了的都不上云。R-18 图（包括本地判的）永远不排队，“让诺诺看看”也会拒绝。
- 怎么看：图缩到长边 1024 左右、去 EXIF 后发给视觉模型，图片放在请求最后，前面是和对话共用的固定前缀（6.8）。一次拿回名字、角色、作品、标签（最多 5 个）、出处、一句话描述（表情包把图里的字原样写出）。
- 查出处（三层，前面能定的就当线索带给后面）：
  1. 本地线索，不调云端：文件名（Pixiv 的 `12345678_p0`、图站的 `__角色_drawn_by_画师__`、`yande.re 12345` 这类能直接认出作品号和画师）；元信息（EXIF 相机型号、拍摄时间、GPS，有相机型号的基本是自己拍的、不再联网；XMP / IPTC 的作者和版权；PNG 文本块里 AI 生图的提示词）。
  2. 看图时顺便联网：同一次看图调用用 Responses 的 `web_search` 工具，本地线索一起放在第④层。Qwen 是看懂图后用文字去搜（认得出的角色作品、图里有签名水印 `@账号` 文字时有效），不是拿图片本身去搜。出处只采用搜索返回的来源链接，不采用模型自己写的链接。
  3. 兜底：搜不到就留空，由你用“其他 AI 辅助整理”交给自己的 AI。真正的以图搜图 `image_search`（要公网 URL、按次收费、一次约 1 分钟）只在你对某张图手动点“查出处”时用。
- R-18 图只做第 1 层的本地线索，不进大模型、不联网。
- 联网搜索只在需要时开：拍的照片（有相机型号）和文件名已经给出出处的不搜。
- 队列：并发 2，单次超时 5 分钟，不自动重试，出错的挂标签由你重试。超时那次是否已计费要对账单。
- 结果存 `image_ai_result`，进“AI 建议”视图：网格只列有待确认建议的图，详情预览下面是“诺诺的建议”卡，每条（名字 / 标签 / 角色 / 作品 / 出处）有采用 ✓ 和不要 ✕，右上角“全部采用”。采用的名字写进 `display_name`，标签、角色、作品当标签加上，出处写进 `image.source`（迁移 0005）；一句话描述在图还没有描述时直接填上，不单独确认；一张图的建议处理完就离开这个视图，选中下一张；都处理完时显示空状态、详情面板收起。

### 6.6 其他 AI 辅助整理

- 详情面板 R-18 下面一块“其他 AI 辅助整理”：一个内容框，占位文字“辅助提示词给你的AI”，右下角复制按钮。
- 复制的是整理好的完整提示词：任务说明；这张图已知的信息（文件名、尺寸和大小、现在的名字、已有标签）；我的整理习惯（来自核心档案）；图库里已有的标签按分类列出（只取非 R-18 图上的）；要求（不编造、不确定写空字符串、字数上限、标签不和已有的重复、只输出一个代码块）；输出格式和一个填好的例子。
- 输出格式是 json 代码块，字段 `name`、`character`、`work`、`tags`、`source`、`description`。
- 你把图和提示词发给自己的 AI，再把回复整段贴回框里：本地找出 json 代码块并解析（找不到时提示“没找到 json 代码块”），显示“识别到 N 条”和“交给诺诺整理”。整理在本地完成：对齐你的叫法和已有标签（含别名）、合并重复、归到正确的分类，结果进“AI 建议”，来源记为外部 AI。R-18 图也可以用这条路，整个过程不调云端。

### 6.7 找图

- 本地路由优先：用词典匹配问题里的标签、别名、目录名，加几个固定句式（竖图 / 横图 / 方图、最近导入、还没打标签），再去掉问句的壳子（帮我找、有没有、的、图……）。剩下的字一个不剩才算完整对上：直接在本地查库、用模板回复（“找到 N 张。没有算上 R-18 图。”），不调模型；有一个字对不上就进对话循环。多个标签之间是“都要有”，条件按在问题里出现的顺序显示。
- 检索两路：关键词（标签名、别名、名字、文件名、描述的 `ILIKE`）和语义向量（只覆盖已生成向量的图，相似度低于 0.35 的不要），按排名融合（RRF，K = 60）。模型给的角色、作品、地点、标签先按标签名和别名精确对，对上了按标签查（之间都要满足），对不上的当关键词；关键词之间任一对上就算（模型常把同义词一起给，比如“夜景、夜晚”）。输入框选的目录作为过滤条件传下去。查询文本的向量按原文缓存在本地。
- 按图找相似：上传或粘贴的图先缩到长边 512，过本地分级闸门（判为 R-18 或模型还没准备好都不上云，直接报错），再生成向量比对，相似度低于 0.6 的不要（构图相近但内容不同的约 0.54）。不调对话模型。
- 补向量：过了上云闸门、还没有向量的图在空闲时逐张实时补（缩到长边 512，一张间隔 0.3 秒，扫描开始或退出时停），分级判完一轮后接着补。向量接口走百炼原生的多模态向量端点，不在批量推理里，所以不走批量。查询文本的向量缓存在内存里（最多 500 条，重启清空）。
- “包含 R-18”打开时：R-18 图只在本地按关键词检索；模型只知道“另有 N 张 R-18 图”，图片和它们的名字、标签都不发给模型，界面直接显示这些图。R-18 图不生成向量。

### 6.8 成本与缓存

百炼规则【已核实，见[上下文缓存](https://help.aliyun.com/zh/model-studio/context-cache)、[批量推理](https://help.aliyun.com/zh/model-studio/batch-inference)】：显式缓存在消息里打 `cache_control` 标记，写入按输入价 125%、命中 10%，有效期 5 分钟、每命中一次重新计时，一个请求最多 4 个标记，每块至少 1024 token，工具定义也算前缀；隐式缓存自动生效、命中 20%、不保证命中；批量推理半价、异步返回。批量能否叠加缓存折扣【待验证：对账单】。

- 所有调用共用同一个前缀，按稳定程度排：

| 顺序 | 内容 | 变化频率 | 缓存标记 |
|---|---|---|---|
| ① | 固定规则、全部工具定义、所有输出格式 | 只在应用升级时变 | ①②合起来一个 |
| ② | 核心档案和标签词表快照 | 最多一天一次 | ①②合起来一个 |
| ③ | 这段对话的历史 | 只往后追加 | 打在最后一条回复后面 |
| ④ | 当前时间、检索到的记忆、这句话或这张图 | 每次都变 | 不打，永远放最后 |

- 守住前缀不变：工具集固定、序列化固定（键名和标签顺序固定、不带时间戳）；会话锁定档案版本；检索到的记忆放在第④层，下一轮自然成为历史被缓存；不压缩历史，对话太长时带一份摘要开新对话（只付一次不命中）；看图队列一张接一张发，间隔在 5 分钟内。
- 预计 5 分钟内还会再调用的（对话、队列）打显式标记；只调一次的任务不打，走隐式缓存，免得白付 125% 的写入费。不为了续期缓存发空请求。
- 能等的走批量：一次排进 50 张以上的看图。平时零散的新图实时看，批量排队太久（实测一条也要 20 分钟以上）。做梦一天最多调一次模型、向量端点不支持批量，这两样都在空闲时实时调。
- 能不调就不调：本地找图路由、外部 AI 结果的本地整理、本地规则提炼偏好、查询向量本地缓存、以图搜图默认不用。
- 记账：每次调用把输入、命中缓存、输出 token 记进 `api_usage`，按调用类型统计命中率；对话和队列低于 95% 时写一条警告日志，只在开发日志里，界面不显示。
- 看图的图片 token 每张都是新的，命中率天然只有一半左右，这类调用靠少调、缩图、批量半价来省，不计入 95% 的目标。

Phase 0 实测（2026-11-14）：
- PGlite 0.5.16 + pgvector 0.8.7 在 Electron 主进程正常，`vector` 余弦距离可用，Drizzle 能定义 vector 列。
- WD swinv2-v3，CPU 2 线程约 1 秒一张，内存峰值约 0.8 GB。
- OSS 私有上传、签名 URL、删除、删除后 404 自检都正常，单次上传约 0.3 秒。
- `image_search`：认对了 Gawr Gura、甘雨、芙兰朵露；一次调用 60–170 秒，大头在服务端搜图；4 个并发时有 2 个超时；百炼 Responses 不遵守 `max_tool_calls`，用量要自己卡；模型写出的链接不可信，出处只用工具结果。flash 的图中文字转写比 max 略差（“好椰”写成“好榔”）。
- 不拿真的敏感图去测云端会不会拒绝（账号有风险），只靠本地闸门挡住。

AI 前置实测（2026-11-22，测试图是画出来的，没用真实图片）：
- 函数调用：一句“找原神里甘雨的竖图，秋天落叶的”能正确调 `search_images` 并拆出作品、角色、方向和语义描述。
- 显式缓存：system 打标记约 6000 token，第一次写入 5997，第二次命中 5997（99.8%）；工具定义算在前缀里。多轮对话在最后一条历史上打标记，下一轮连历史一起命中。用量字段：Chat 是 `prompt_tokens_details.cached_tokens` / `cache_creation_input_tokens` / `image_tokens`，Responses 是 `input_tokens_details.cached_tokens` / `cache_write_tokens`、图片在 `x_details`、搜索次数在 `x_tools.web_search.count`。
- 思考必须关：Node SDK 没有 `extra_body`，百炼参数直接放请求顶层（`enable_thinking: false`）。不关时带图联网一次 16.7k 输入、7.1k 输出、约 130 秒；关掉后 2.4k 输入、62 输出、约 4 秒。
- 同一张 768×512 的图，Chat 记 386 个图片 token，Responses 记 772 个。
- 批量推理：一个批次里不能混用带图和纯文本的请求（报 `all request must be multimodal or plainText, cannot be mixed`），看图和做梦要分开提交。base64 带图的批次能用（只有一条时也排队约 20 分钟才完成）；批次里开联网搜索也能用（排队约 47 分钟）；只有一条纯文本的批次超过 55 分钟还没完成。

### 6.10 一键整理

目的是让类目录井井有条，同时兼顾便宜和好用：只有看图和出方案调云端，把图分进目录在本地做；所有结果都进“AI 建议”由你审，不直接动类目录。

- 入口：底栏“诺诺在看图”右边的“一键整理”。点了先弹确认卡片：渐变底的标题区（右上角 × 是暂时不整理），三格数字（要看多少张——还没看过、还没打标签、过了上云闸门的图，包括看图功能上线前的老图；大概多少 token；大概多少钱），三行一句话的说明，一个独占一行的“开始整理”。本地分级还没做完也能开始：先用已经判完的图出方案；张数和花费按剩下的最多都要看来算（标“最多”），并提示“本地分级还剩 N 张，判完的半价陆续补进来”。R-18 图不看、不分，只走本地分级。
- 补图：方案批了以后进入“整理中·补图”，记住批过的方案。分级每判完一小批，判完、过了闸门、还没看过的老图就排进看图队列，但只走批量推理（优先级为负，攒够 100 张交一批，分级判完了就把不满一批的也交了；半价、不联网），看完攒几秒按方案分一次。分级全判完、看图队列也空了，最后分一次，回到空闲。中途停止会取消还没交出去的补图。
- 三步：
  1. 看图：上面那些图排进看图队列（50 张以上的部分照旧走批量）。
  2. 出方案：队列看完后，一次纯文本调用（flash、关思考）：给模型现有类目录、非 R-18 图上的标签和待确认建议里的角色、作品、标签的统计，让它出一份类目录方案：沿用哪些已有的、新建哪些（最多 12 个，名字最多 15 个字），每个目录收哪些角色、作品、标签（只能从给它的词里选）。
  3. 你批方案：方案弹窗里可以改目录名、去掉目录、去掉某个词，“按这个方案整理”后在本地分图：每张非 R-18、还不在任何类目录里的图，用它已有的标签和待确认的建议去对方案，角色优先、其次作品、再次标签，对上的生成一条“放进类目录”的建议；对不上的不管。
- 状态记在 `app_setting` 的 `ai.organize`（看图中 / 出方案中 / 方案待确认 / 补图中 / 空闲，带方案）；按钮跟着显示“整理中·看图”“方案待确认”“整理中·补图”。退出后重开接着来。
- “放进类目录”建议：`image_ai_result` 新的 `ORGANIZE` 类（迁移），`field_status` 键 `dir`。采用时目录不在就建（类目录根下一层），然后复制进去（源目录里的原图不动），和“复制到”走同一套，可撤销。
- “AI 建议”视图：按建议生成的先后排，后来的接在最后；有“放进类目录”建议的按目标目录分组，组头“→ 猫猫（新建）· 23 张”和“这一组全部采用”；多选后批量面板里“全部采用 / 全部不要”；选中单张时 A 全部采用、X 全部不要，然后选中下一张。
- 采用、拒绝都进事件流，做梦时整理成偏好，下一次方案和建议会更贴近你的习惯。

## 7. 界面规范与风格

- 主题角色是用户自己设计的诺诺（设定以个人网站 `nuonuo_role` 为准）。插画在 `src/renderer/src/assets/nono/`：标题栏旁不放看板娘；第一次打开（挥手）、空状态（往空纸箱里看）、图库打不开（抱着上锁的相册）各一张，透明底，不跟深色变色。应用图标是 Codex 画的照片卡片 + 白色卷尾 + 粉缎带铃铛（`resources/icon.png`，`node scripts/make-icon.mjs` 生成 ico 和标题栏小图），生图做法见 [`codex-imagegen.md`](codex-imagegen.md)。
- 窗口不用系统标题栏，标题栏和最小化、最大化、关闭三颗按钮自己画。
- 清爽、有呼吸感：
  - 背景不抢主视觉；顶栏不画底色；底栏一整条，上沿一根细线、很淡的玻璃底，左边 AI 胶囊，右边数量、扫描状态和“重新扫描”；
  - 侧栏每个分组是一张悬浮的玻璃卡片，详情面板是一整块玻璃，筛选栏是玻璃胶囊；都是圆角、四周留 14px、主题色细描边、很淡的投影；默认组件透明度 40% 时能透出背景，鼠标移上去缓缓变实；
  - 缩略图底下垫一层很淡的磨砂白，悬停浮起、底色变实，选中白底加主题色描边；
  - 面板里的小卡片用细白描边配半透明白底；数量徽标用淡主题色胶囊；
  - 小装饰点到为止。
- 不用悬停小字提示（原生 title），图标按钮只留 `aria-label`；名字被省略号截断时悬停显示全名。
- 开关：关着是中性白底（深色下浅一层的底）加灰圆点，开着才用强调色（R-18 红色，其余主题色）。
- 对话框：右上角“×”和“取消”不同时出现；底部只有一个按钮时要么占满一行、要么不放；两个以上等宽并排；危险操作默认聚焦安全的按钮。弹出卡片和菜单带指向来源的尖角。
- 深色模式：默认背景深紫黑加一团主题色柔光，主题背景换各自的深色版；主题色派生色往深底上混；写死的颜色按用途换（浅底和线条变同色相的深色，深字和图标变同色相的浅色，语义色保留色相，按钮和角标上的白字不变）；图片本身不跟深色变。所有状态、对话框、菜单都要在深色下检查。
- 过渡动画（流畅优雅、不过多，写在 `styles/global.scss` 末尾）：弹窗遮罩淡入、卡片从下方 8px、0.97 倍浮起（进 0.2–0.26 秒，出 0.15 秒）；下拉、右键菜单淡入并从上方落下 4px；页面切换先淡出再淡入；换视图或筛选时网格整体淡入（扫描中的刷新不淡入）；可点的东西悬停、选中时 0.15 秒过渡，按钮按下轻轻一沉。只动 opacity 和独立的 translate / scale；系统开了“减少动画”时全部几乎瞬间完成。

## 8. 测试与工具

- 单元测试 `npm test`；端到端 `npm run build` 后 `npm run test:e2e`（Playwright 驱动 Electron，每个场景用独立的 `D:\ltm-dev\e2e\<场景>`）。
- `tests/e2e/assistant.test.ts` 走一遍诺诺助手（本地路由、开 R-18、交给模型的一问、大图、范围、对话记录、没有凭证的整页提示），交给模型的那一问会真实调用百炼（约 3k token）。
- `tests/e2e/rating.test.ts` 用渐变测试图走本地分级：正常阈值下不打 R-18；`LTM_R18_THRESHOLD=0`（测试用，只能往下调）时全部判成 R-18、标“诺诺判的”，手动关掉后重启也不会被判回来。
- `tests/e2e/look.test.ts` 导入两张画出来的图，真实调用百炼看图（实时、带联网），检查底栏胶囊、AI 建议视图、建议卡的采用和不要；`semantic.test.ts` 真实补向量，上传一张相近的图只找回同类的那张；`organize.test.ts` 看底栏本地分级进度，真实出一份类目录方案、批方案、按目录分组审、一组全部采用后检查文件复制进了类目录；`drag.test.ts` 只验证原生拖拽能找到原文件并正常返回（真的拖要人按住鼠标）。
- `tests/e2e/usersim.test.ts` 把主要操作都点一遍，全程收集控制台报错和未捕获异常，必须为空；`extreme.test.ts` 覆盖空文件、坏文件、超大图、极端比例、深目录、怪文件名、运行中源目录被删等；`tour.test.ts` 在浅色、深色下各走一遍主要页面并截图（`test-output/phase1/app/tour-*.png`），改界面后对照检查。“打开文件夹”类按钮在测试里只记录、不弹资源管理器。
- README 截图由 `LTM_SHOTS=1` 时的 `readme-shots.test.ts` 生成（画出来的风景图，不用真实图片）；README 的图片放 OSS `zlhimage` 的 `item_picture/nuonuo_tool_center/readme/`，不进仓库，不写图片怎么生成的。
- 原型预览：`node docs/prototype/tools/render.cjs` 把原型按预设展开成静态 HTML（见 [`prototype/README.md`](prototype/README.md)）。

## 9. 范围与阶段

**已完成（P0）**：导入、扫描、缩略图、实时监听；网格浏览、筛选、多选；名字、标签、R-18 手动标记；删除、移动、复制和撤销、崩溃对账；目录管理；标签管理；大图；设置；各种特殊和异常状态。

**AI 阶段开工顺序**（7 步都已完成；还没做的：`propose_file_ops`、“从图库里挑一张”）：
1. 前置：补 AI 相关表和迁移；`api_usage` 记账；百炼客户端统一前缀和缓存标记；验证函数调用、显式缓存、base64 传图、批量推理。
2. 诺诺助手：harness、本地找图路由、关键词检索、对话页和对话记录、反馈。
3. 本地分级：WD 挪进 utilityProcess，扫描后补判，“诺诺判的”。
4. 看图队列和 AI 建议：底栏胶囊、AI 建议视图和建议卡；其他 AI 辅助整理。
5. 记忆：事件流、`remember`、做梦、核心档案。
6. 语义向量和按图找相似（向量模型先验证）。
7. 长按拖出到别的软件（5.2）。

**暂缓**：手机访问、本地 OCR、SauceNAO 和图站哈希查出处、MCP 插件（让用户的 Codex、Antigravity 等 agent 连进来导入整理结果）、Gemini、工具箱框架、打包分发、在线更新、恢复备份。

**重复图片（暂缓，方案留作以后参考）**：完全相同（内容哈希相同、出现在多处，应用自己“复制到”的副本不算）建议保留最早导入的；画质不同（感知哈希距离在阈值内、长宽比接近，同名 RAW+JPG 不算）建议保留像素最多的，像素相同时优先无损格式再比大小。每组标“建议保留”，其余可勾选删除或一键“只留建议的”，顶部显示可释放空间；删除走确认、进回收站、每组至少留一份。
