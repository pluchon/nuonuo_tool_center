# 本地图库管理工具：设计方案（定稿草案）

> 状态：方案已确认，骨架已搭好，Phase 0 验证结果见第 8 节。标注【已核实】的结论有文档或实测依据；标注【待验证】的放到 Phase 0 去测，测完再回填。

## 1. 目标与边界

只给自己用的 Windows 桌面软件。导入几个图片目录（二次元图、表情包），可以管理、打标签、搜索。AI 只在需要时帮忙：查出处和角色、写描述、起名、整理目录。

- 打标签以手动为主，AI 是兜底：先自己填，填不出来再点“让 AI 看看”。
- 云端只接阿里百炼，凭证从用户环境变量读取（`DASHSCOPE_API_KEY`、`ALIYUN_ACCESS_KEY_ID`、`ALIYUN_ACCESS_KEY_SECRET`），不进代码、不进库、不写日志。
- 原目录允许改动（移动、改名、删除）。删除一律进系统回收站（Windows 回收站），应用里不另设回收站和操作记录页面（用户决定，2026-11-15）。
- 敏感图片永远不上云，也不进 AI 检索；传统检索（标签、名字、描述关键词）照常能搜到。

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | Electron + TypeScript，用 electron-vite 构建 | |
| 界面 | Vue 3 + Pinia + Element Plus | 遵守全局前端规范：组件拆成 `.vue/.ts/.scss`，页面只通过 `src/api/` 调用，状态只通过 action 修改 |
| 数据库 | PGlite（内嵌 PostgreSQL）+ pgvector | 不用安装数据库服务。SQL 只写标准 PG 语法，以后换成真 Postgres 只改连接配置 |
| ORM / 迁移 | Drizzle ORM（有 pglite 驱动），迁移只往前加 | 用类型安全的列引用，不写字符串列名【已核实：支持 vector 列】 |
| 本地推理 | onnxruntime-node，只跑 WD tagger 做**内容分级** | 只用 CPU，限 2 线程【已核实：约 1 秒一张】 |
| 图片处理 | sharp | 生成缩略图、上传前缩图、去掉 EXIF |
| 云端 | 百炼 Responses API + 阿里云 OSS | 见第 6 节 |

全项目只有一种语言，不需要 Python。

## 3. 进程与分层

```
渲染进程 (Vue)
  views → stores(actions) → src/api/*  ──IPC──┐
                                             │  preload：只暴露带类型的 window.api
主进程                                        ▼
  ipc/*（只做参数校验和调用）→ services/*（业务、事务、状态流转）→ repositories/*（Drizzle）→ PGlite
  ├─ workers/rating      WD 分级（utilityProcess，不卡主进程）
  ├─ workers/thumbnail   sharp 生成缩略图
  ├─ services/fileOps    唯一允许写文件系统的地方，操作串行排队执行
  ├─ services/cloud      OSS 临时上传 + 百炼调用 + 额度控制
  └─ services/assistant  AI 助手（函数调用）+ 记忆
自定义协议 ltm://thumb/{hash}、ltm://file/{fileId}
  图片走协议直接加载，不经过 IPC 传 base64；只允许访问已登记目录里的文件
```

安全设置：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`，并配置 CSP。渲染进程不能读任意路径。

## 4. 数据模型（PostgreSQL）

所有业务表都有 `id BIGINT GENERATED ALWAYS AS IDENTITY`、`create_time`、`update_time`、`delete_state`，默认逻辑删除。状态一律用枚举，不用魔法数字。

| 表 | 作用 | 关键字段 / 约束 |
|---|---|---|
| `library_root` | 导入的目录 | `path`（规范化后加唯一索引）、`name` |
| `image` | **按内容去重的图片**，标签和描述挂在这里 | `content_hash`（sha256，唯一）、宽高、格式、`display_name`（AI 或手动起的名字，只存在库里）、`description`、`rating`、`rating_source`（MODEL/MANUAL）、`rating_scores jsonb` |
| `image_file` | 图片在磁盘上的位置，同一内容可以有多个位置 | `image_id`、`root_id`、`rel_path`；`(root_id, rel_path)` 在未删除记录内唯一；`status`（NORMAL/MISSING/DELETED） |
| `tag_category` | 标签分类（用户在标签管理里维护） | `name`（唯一）、`color`、`sort_order`；默认四个：角色、作品、画师、主题；还有标签在用的分类不能删 |
| `tag` | 标签字典 | `name`（去空格、统一大小写后唯一）、`category_id`（引用 `tag_category`） |
| `image_tag` | 图片和标签的关联 | `source`（MANUAL/VLM）、`status`（ACCEPTED/SUGGESTED/REJECTED）；AI 给的标签先是 SUGGESTED，你确认后才生效 |
| `image_ai_result` | 每次云端分析的完整结果 | `kind`（IDENTIFY/DESCRIBE/NAME）、`model`、`result jsonb`（含出处链接、角色、作品）、`usage jsonb` |
| `image_embedding` | 语义向量 | `image_id`、`model`、`embedding vector(1024)` |
| `file_op_batch` | 一次整理操作 | `origin`（USER/AI）、`summary`、`status`（PLANNED/APPLYING/APPLIED/UNDONE/FAILED） |
| `file_op` | 整理操作里的每一步 | `op_type`（MOVE/COPY/RENAME/DELETE）、`from_path`、`to_path`、`content_hash`、`status`、`error` |
| `api_usage` | 云端调用流水，用来卡额度 | `api`、`units`、`est_cost`、`image_id` |
| `ai_conversation` / `ai_message` | 助手对话 | |
| `ai_memory` | 助手的长期记忆 | `content`、`kind`、`embedding vector(1024)`、`source_message_id` |
| `app_setting` | 配置 | key/value，存 OSS bucket、region、每日额度等，不存密钥 |

规模估算：几千张图，向量直接暴力计算相似度，先不建 HNSW 索引。

## 5. 核心流程

### 5.1 导入与扫描
1. 选择目录，登记为 `library_root`。
2. 递归扫描支持的格式（jpg/png/webp/gif/bmp/avif，以及摄影常见的 heic/heif 和相机 RAW：arw/cr2/cr3/nef/dng/raf/orf/rw2；RAW 和 HEIC 用 sharp/libraw 或系统解码生成缩略图）。扫描时读 EXIF（机身、镜头、焦距、光圈、快门、ISO、拍摄时间）存进 `image`。
3. 用流式读取计算 sha256，按哈希建 `image` 和 `image_file`，再排队生成缩略图（webp，存在应用数据目录，按哈希命名）。
4. 每次启动时全量对账，运行期间用 chokidar 监听变化。文件被外部删除标为 MISSING；被移动或改名时按哈希自动接回，标签不丢。

### 5.2 敏感度标记与分级闸门（本地）
- 敏感度是一个**由你手动管理的标记**：在界面里给图片打 general / sensitive / questionable / explicit，`rating_source = MANUAL`，手动结果永远优先。
- 本地 WD tagger（swinv2-v3）只做初筛，**只标明显的**：questionable + explicit 分数之和 ≥ 0.5 才判为敏感；轻微的 sensitive 不拦（用户决定放宽，2026-11-14）。
  - 按这个阈值：用户确认安全的 100 张全部放行；随机 40 张拦下 3 张（都是 questionable）。
- “敏感图”的口径：有效分级（手动优先，否则模型）为 questionable 或 explicit。
- 敏感图的处理：
  - 不上云、不进 AI 检索（语义搜索、AI 助手的 `search_images`）；
  - 传统检索（标签、名字、描述关键词）照常能搜到，结果里不做过滤；
  - 有一个专门的视图列出所有敏感图，由你手动归类移走（也可以让助手生成移动计划，确认后执行）。
- WD 打出的内容标签**默认不用**（按“先手动”的原则）。可以在设置里打开“显示 WD 建议标签”。

### 5.3 让 AI 看看（按需、云端）
1. 检查闸门：是敏感图（见 5.2 口径）就直接拒绝，并告诉你原因。
2. 缩图（长边 ≤ 1536，JPEG，去 EXIF），上传到 OSS 的 `local_image_temp/{yyyyMMdd}/{uuid}.jpg`，生成有效期 10 分钟的签名 URL。
3. 调百炼 Responses API（qwen3.8-flash + `image_search` 工具），一次拿回：角色、作品、描述（表情包要把图里的文字逐字写进去）、建议名字、建议标签；出处只取工具返回的结果。
4. 在 `finally` 里删掉 OSS 上的临时对象。另外建议在 OSS 控制台给 `local_image_temp/` 配一条 1 天过期的生命周期规则兜底。
5. 结果整体存进 `image_ai_result`，标签和名字作为建议展示，你确认后才写进 `image_tag` 和 `display_name`。

额度控制：`image_search` 每天调用上限在设置里配，默认 50 次，约 2.4 元【已核实：北京地域 48 元/千次】。上限在调用前用 `api_usage` 检查，由我们自己的代码卡死，不依赖模型侧的 `max_tool_calls`【已核实的坑：百炼 Responses 不遵守 max_tool_calls】。

### 5.4 搜索
- 一个搜索框，同时查三路：标签名、`display_name` 和 `description` 的模糊匹配，以及语义向量（只覆盖已经生成过向量的图）。结果按排名融合（RRF）合并。
- 可以按目录、分级、标签过滤。
- 敏感图（5.2 口径）不参与语义向量这一路，也不生成向量；关键词这一路不过滤。
- 语义向量用 qwen3-vl-embedding：图片向量在“让 AI 看看”时顺带生成，或者对非敏感图批量生成；查询文本每次搜索实时转成向量。

### 5.5 文件整理与删除保护
- `fileOps` 是唯一允许写文件系统的服务，所有操作串行排队。
- 每个批次按 PLANNED → APPLYING → APPLIED 推进。日志**先写库，再动文件**，只用于崩溃后对账：启动时把卡在 APPLYING 的批次逐条和磁盘对账，补完或回滚。界面上不展示操作记录。
- **删除 = 进系统回收站**：用 Electron `shell.trashItem`，删除前一次确认。对应的 `image_file` 标为 DELETED，标签和名字留在 `image` 上；用户从系统回收站还原后，重新扫描按 `content_hash` 认回原来的标签。
- 跨盘移动：先复制，校验哈希，确认一致后再删源文件。
- 目标路径已存在时自动加后缀，绝不覆盖。
- AI 只能生成 PLANNED 状态的批次，界面预览后由你点确认才执行。AI 永远不能直接执行。

### 5.6 AI 助手
- 模型 qwen3.6-plus，带函数调用。只发文字，不发图片；需要它看图时，走 5.3 的闸门流程。
- 工具：`search_images`、`get_image`、`list_tags`、`propose_file_ops`（只生成计划）、`remember`、`recall`。
- 记忆：对话存在 `ai_message`；值得长期保留的事实（比如“我管这个角色叫 X”）由助手调 `remember` 写进 `ai_memory`，向量用百炼文本向量模型【待验证：模型名和维度】。每轮对话开始时按相似度和时间取 top-k 条记忆注入上下文。
- 查询失败和“没有结果”要分开报告，降级时不能冒充语义判断。

## 6.5 界面风格：诺诺的图床（2026-11-15 由“诺诺的图书馆”改名）

- 主题角色是用户自己设计的诺诺（猫耳、淡紫长发、透明雨伞）。插画放在 `src/renderer/src/assets/nono/`，配色都从插画里取：
  - 主色：紫阳花紫；
  - 点缀：发饰的樱粉、灯笼的暖橙；
  - 文字：木色暖褐。
- 窗口不用系统标题栏（`titleBarStyle: 'hidden'`），标题栏由界面自己画。系统的最小化、最大化、关闭按钮保留，按主题换颜色。
- 背景是放大后模糊的插画，叠一层色调和雨丝动画。面板是半透明的“玻璃”效果。
  - 面板不用 `backdrop-filter`：背景已经模糊过了，再加的话，雨丝每动一帧核显都要重新算一次模糊。
  - 雨丝只用 `transform` 动画；系统设置了“减少动画”时自动停掉。
- 两套主题：
  - 浅色“雨天午后”；
  - 深色“夜雨灯笼”：同一张插画调暗，叠加暖色灯光。
- 诺诺本人是看板娘：侧边栏底部放她的头像（从插画里裁出来的）和对话气泡，用来播报状态、空状态和错误。
- 待补的素材，用 Codex 生成，需要用户确认：
  - 诺诺的 Q 版表情（开心、思考、困、出错）；
  - 应用图标；
  - 夜景版插画；
  - 原图的高清版。

### 画布定下的功能约定（2026-11-15）
- “全部图片”只显示打过标签的图；没标签的图只在“还没打标签”里。另有“最近导入”。
- 目录分两种：
  - 源目录：导入进来的原始目录。
  - 类目录：用户自己建的分类目录，放在应用管理的图库文件夹下。
  - 点任一目录，就显示这个目录里的所有图。
- “移动到…”：可以移到任一源目录或类目录，单选。“复制到…”：可以多选目标，源目录和类目录都可以；批量复制时所有图平铺放进目标文件夹，不保留原来的子目录结构，文件重名自动加编号。一张图可以同时出现在多个类目录里，复制会在磁盘上真的复制出文件，所有记录按内容哈希归到同一个 `image` 下。
- 敏感度简化成一个开关：是不是 R-18。打开后网格里遮挡；“整理”里的页面叫“R-18 图”。
- 名字最多 15 个字，每张图最多 5 个标签。筛选时标签、目录各最多选 5 个，排序只能选一种：最近导入 / 最早导入 / 拍摄时间 / 文件大小 / 名称。
- 摄影图：详情面板在文件信息下方显示拍摄信息（机身、拍摄时间、镜头、焦距 / 光圈 / 快门 / ISO），没有 EXIF 的图不显示这一块。详情面板内容超出时整体滚动。
- 类目录存放在应用管理的图库文件夹（默认 `D:\诺诺图床\`）。
- 字数上限不在输入时截断（会打断中文输入法），超出时计数变红并禁止保存。
- 删除进系统回收站，没有应用内的回收站和操作记录页面。
- R-18 图：一个图库视图，只列开了 R-18 的图，右侧照常是图片编辑面板；缩略图在所有视图里默认模糊，选中后详情和大图正常显示。在这个视图里关掉开关，图就离开列表。
- 标签分类由用户维护：标签管理页分类页签末尾的编辑按钮打开“标签分类”对话框，可以改名、新增，删除只对没有标签在用的分类开放。给图片加标签时，“+”右侧选分类；输入的是已有标签就沿用它的分类，不能在这里改。
- 筛选下拉、移动/复制对话框的列表都限制可见行数（筛选 10 行、对话框每组 5 行），多了在框内滚动。
- 移动到源目录时可以逐层展开子文件夹，选到任意一层。实现用 Element Plus 的 `el-tree` 懒加载（`lazy` + `load`，子文件夹通过 IPC 读 `fs.readdir(withFileTypes)`，只列文件夹），不自己写树；打开对话框时自动展开到当前所在位置。
- 大图查看：放大后按住左键拖动平移，Ctrl + 滚轮缩放（25%–400%），缩回 100% 以下自动回中。
- 导入源目录：点侧边栏“源目录”的“+”，弹出和移动/复制同样的选择对话框，按磁盘逐层展开选文件夹；已导入的目录、它的子目录、包含已导入目录的上层、应用自己的图库文件夹都不能选。实现同样用 `el-tree` 懒加载。
- 源目录图标：有子文件夹的显示多文件夹图标，没有的显示单文件夹图标。
- 源目录视图的筛选：按图片名搜索。子目录靠左侧目录树切换，不再有目录筛选下拉；当前目录有子目录时，筛选行最右侧（前面一条竖线隔开）有“仅展示当前目录图片（不含子目录）”开关，默认关，即包含所有子目录里的图。
- “还没打标签”和“最近导入”只有按图片名搜索，不放标签、排序、R-18 和“已选”区。“还没打标签”另有一个平铺的目录筛选：只列含未打标签图的目录（源目录和类目录都算，不展开子目录），少于两个目录时不显示；要按子目录看就进对应的源目录。“最近导入”不加目录筛选，按导入时间排、详情里有导入时间就够。
- 类目录支持子目录，不限层数。侧边栏类目录是可展开的树：卡片标题的“+”建顶层；鼠标移到某一行时，行尾的数量换成“+”，点它在这一行下面建子目录。新目录行直接在对应位置出现输入框，默认名“未命名的类目录 / 未命名的子目录”，同级重名自动加编号。
- 源目录在侧边栏同样是可展开的树，子文件夹来自磁盘扫描，可以点进任一层查看（筛选同源目录规则）；源目录每一行也有“+”，在磁盘上新建子文件夹（默认名“新建文件夹”，不限层数）；在资源管理器里新建的文件夹在下次扫描后出现。展开的树用细线连接父子（竖线 + 圆角拐角），最后一个子项的竖线到拐角为止。
- 类目录视图的筛选：搜索、标签、排序、R-18 照常；同样没有目录筛选下拉，有子目录时末尾有“仅展示当前目录图片（不含子目录）”开关。全部图片、R-18 图里的目录下拉只列顶层目录，选父目录包含所有子目录里的图。
- 复制/移动对话框里类目录也是可展开的树，打开时自动展开到已有副本或当前位置。有子目录的文件夹统一用叠放的多文件夹图标，类目录是带爱心的版本。
- 加标签时按输入的关键字匹配已有标签的名字和别名，最多列 5 个（前缀匹配优先，其次按图片数），没有匹配就不出列表；已经在这张图上的标签不列。

- 多选：网格里 Ctrl 点击逐张加选、Shift 点击按当前顺序连选，Ctrl 点击已选中的图只取消这一张（剩一张时回到单选），普通点击回到单选（与 Windows 资源管理器一致）；一次最多 200 张，超出时提示“一次最多选 200 张”。选中 2 张及以上时右侧变成批量面板：共同标签（可一起移除）、给这些图一起加标签（超过 5 个的图跳过）、全部标/取消 R-18、复制到/移动到、删除这 N 张（确认后进系统回收站）。
- 目录右键菜单（贴在所点目录下方，带指向该目录的尖角，半透明磨砂底）：类目录有“新建子目录 / 重命名 / 打开所在文件夹 / 删除”；源目录顶层有“新建子文件夹 / 重新扫描 / 打开所属源目录 / 从图库移除”（移除只是不再管理，磁盘文件不动），源目录子文件夹只有新建和打开。新建子目录只走右键菜单，行上不再有悬停“+”。
- 重新扫描：底栏扫描时间旁边有“重新扫描”，扫描中显示“正在扫描…”；源目录右键菜单里也能对单个目录重新扫描。
- 缩略图大小：在网格上 Ctrl + 滚轮在 5 档行高之间切换（大约每行 3 到 8 张的密度），默认中间档。
- 拖拽：只能拖到源目录（含子文件夹）上，类目录不接收拖放（分类靠右侧面板的复制/移动）。直接拖是复制、按住 Ctrl 拖是移动，松手后弹确认框再执行；拖动时跟手的是一个小方块缩略图（多张时角上显示张数），多选的一组可以一起拖。
- 快捷键（原型已实现）：大图里 ← / → 上下张（两侧也有上一张 / 下一张按钮）、Esc 关闭；网格里 ← / → 移动选中，↑ / ↓ 跳到上 / 下一行水平位置最近的那张，Enter 打开大图，Delete 删除（走确认），Ctrl + A 全选当前列表（最多 200 张），Ctrl + C 复制图片（多选时复制文件）；对话框和菜单里 Esc 关闭。
- 勾选圈（类似 Google 相册）：鼠标移到缩略图上右上角出现圆圈，点它等于 Ctrl + 点击；进入多选后所有图都显示圆圈。
- 操作提示：删除、移动、复制完成后从窗口顶部弹出提示条（下滑弹入动画），5 秒后消失；移动、复制、删除都可以“撤销”。删除的撤销做法：先在库里隐藏，提示条消失（或应用退出）时才真正 `shell.trashItem`。
- 特殊与异常状态（画布第二、三排，草案待定）。原则：状态提示只写标题和操作按钮，不写解释性文字（用户定，2026-11-15）：
  - 第一次打开（还没有源目录）：主区只有一个透明底的诺诺插画占位，下面一个“选择图片文件夹”按钮，不放其他说明（也支持把文件夹拖进窗口）；侧栏源目录、类目录显示虚线占位。
  - 导入或重新扫描时：图片区上方一条进度横幅（“正在扫描「X」 已处理 / 总数 · 已找到 N 张图” + 进度条 + 停止扫描），侧栏对应源目录显示“扫描中”；还没生成好的缩略图显示流光占位，扫描完弹提示。
  - 源目录找不到（移动硬盘没接、文件夹被移走）：侧栏该目录标“找不到”（橙色）；进入后横幅只有“文件夹带 × 图标 + 找不到 <路径>”和“重新选择”按钮，不显示原因（选新位置后恢复），不放解释；缩略图用缓存显示为灰色，详情面板只显示“原图暂时打不开”，复制 / 移动按钮不可用。
  - 单张图异常：文件不见了（粉色斜纹占位，详情面板只显示“文件不见了”标题，删除用预览图上已有的删除按钮）；无法预览（损坏或不支持的格式，详情面板只有“无法预览”标题和“用默认程序打开”按钮，名字和标签照常可改）。
  - 空状态（搜索没有结果、筛选后没有图、目录为空）：只有一个透明底诺诺插画占位 + 一行字（如“没有找到「关键词」”），不放提示和按钮。
  - 操作失败：顶部提示条换成红色图标，不自动消失，点“知道了”关闭，例如“有 2 张没复制成功：D 盘空间不足”。
  - 图库数据打不开：整窗只有透明诺诺插画占位 + 一行标题直说发生了什么（“图库数据被占用，暂时打不开” / “图库数据损坏，暂时打不开”）+ “重试”按钮。
- 所在目录不再作为筛选标签显示（左侧已经高亮）。

- 网格排版：按原比例排成行，**所有行同一高度**，宽度随比例变；行末用“整行略压窄”或“把最后一张挪到下一行、整行略撑宽”中变形更小的一种对齐右边，图片按 cover 裁掉多出的一点；最后一行不拉伸。长宽比限制在 0.5–2.5：超宽（全景、带鱼屏）和超长（长截图）只显示中间部分，左下角标“全景”/“长图”，双击看完整图。Ctrl + 滚轮在 5 档行高之间切换。每张缩略图右下角压一个半透明的格式标记（JPG / PNG / GIF / WEBP / RAW / HEIC…），下方只放名字。
- 按月份分组（类似 Google 相册，保持简单）：排序为“最近导入 / 最早导入”时按导入月份，“拍摄时间”时按拍摄月份（没有拍摄时间的归到最后一组）；按文件大小、名称排序时不分组。组头直接放在图片区域里、滚动时吸顶，左边一根紫粉渐变竖条 + “2026 年 11 月”粗体标题，中间虚线，右边是“选择本月 / 取消选择”按钮和“N 张”胶囊。单张图的操作都在右侧详情面板，缩略图不做右键菜单。
- RAW 和同名 JPG 分开显示，各算一张。
- 更多筛选（工具栏“更多”）：格式、方向（横/竖/方）、尺寸（4K 及以上 / 1080p 及以上 / 1000px 以下）、文件大小（1 MB 以下 / 1–10 MB / 10 MB 以上）、拍摄时间（近 30 天 / 今年 / 去年 / 没有拍摄时间）。同一组内是“或”，不同组之间是“与”；选中的条件进上方筛选标签。只在全部图片、R-18 图和类目录里出现。
- 一次最多选 200 张。
- 标签分类：预设角色、作品、画师、主题、地点、人物、器材、风格，共 12 种主题色。新建分类随机取一个还没被占用的颜色；分类卡片标题右侧有调色板按钮，可换成其他未被占用的颜色。
- 重复图片（“整理”里的独立页面）：
  - 完全相同：内容哈希相同、出现在多个位置的文件。应用自己“复制到…”产生的副本是有意为之，不算重复。建议保留最早导入的那份。
  - 画质不同：感知哈希（dHash/pHash）距离在阈值内且长宽比接近，但分辨率、格式或压缩不同。同名的 RAW+JPG 成对照片不算。建议保留像素最多的；像素相同时优先无损格式（RAW > PNG/TIFF > WEBP/HEIC > JPG/GIF），再比文件大小。
  - 每组标出“建议保留”，其余可勾选删除，或一键“只留建议的”；顶部显示可释放空间和“全部只留建议的”。删除走确认，进系统回收站，每组至少留一份。

### 界面规范（用户定，2026-11-15）
- 不写小字说明，需要说明时一句话说清；能用数字和状态表达的不用句子。
- 排版舒适：一行的最左边和最右边都可以放内容，比如左边标题、右边数量或按钮。
- 卡片用清晰的边框配白底，不用阴影和厚重的填充。
- 对话框：
  - 右上角的“×”和“取消”按钮不同时出现；
  - 底部只有一个按钮时，要么占满一整行，要么干脆不放；
  - 两个及以上按钮时，在同一行等宽并排；
  - 危险操作默认聚焦在安全的那个按钮上。

## 7. 目录结构

```
local_tool_manage/
  src/main/      index.ts  ipc/  services/  repositories/  db/(schema, migrations)  workers/  protocol/
  src/preload/   index.ts
  src/renderer/  api/  stores/  views/  components/
  docs/          design.md
  test-output/   临时脚本和截图（加入 .gitignore）
```

模型文件（WD onnx，约 450MB）首次运行时下载到应用数据目录，不进仓库。数据库目录在 `%APPDATA%\LocalToolManage\pgdata`。

桌面快捷方式不打包：直接用项目里的 `electron.exe` 启动构建产物（`out/`），所以改完代码要先 `npm run build` 快捷方式才会生效。开发模式和快捷方式共用同一个数据目录，靠单实例锁保证同一时间只有一个进程打开 PGlite。

## 8. 范围与阶段

**Phase 0：技术验证**（2026-11-14 实测结果）
- V1 ✅ PGlite 0.5.16 + pgvector 0.8.7 在 Electron 45 主进程里正常：首次启动约 3 秒建好 14 张表，正常关窗后数据完整，`vector` 余弦距离可用，Drizzle 能定义 vector 列。PGlite 0.5 没有 pg_trgm，模糊搜索先用 `ILIKE`（几千行足够）。
- V2 ✅ WD swinv2-v3，CPU 2 线程：约 1 秒一张，进程内存峰值约 0.8GB。未测 DirectML（核显曾整机卡死，暂不碰）。
  - 用户确认安全的 100 张：85 张 general 放行，15 张判为 sensitive 被拦（其中约一半 general 和 sensitive 分数接近，属于偏保守误拦，可以手动改分级放行）。
  - 随机 40 张：21 张 general、16 张 sensitive、3 张 questionable、0 张 explicit，被拦 19 张。准确率需要用户抽查被拦的文件名。
- V3 ✅ OSS 私有 ACL 上传、签名 URL、删除、删除后 HEAD 404 自检，全部正常；单次上传约 0.3 秒。
- V4 ⚠️ `qwen3.8-max` + `image_search` 可用，`dashscope.aliyuncs.com` 端点不需要 WorkspaceId。
  - 准确度：5 张里成功的 3 张都认对了（Gawr Gura、甘雨、芙兰朵露），甘雨表情包的图中文字“好椰”也正确转写。
  - 耗时：一次调用 67~172 秒，大头在服务端以图搜图本身（单次约 2 分钟）；4 个并发时有 2 个超过 5 分钟超时。

  - 改用 `qwen3.8-flash` 复测甘雨那张：60 秒，只搜一次，角色认对（置信 0.95），约 5.4k token；图中文字转写成了“好榔”（max 是“好椰”），OCR 略差。服务端搜图本身仍要约 1 分钟，后台队列的设计不变。
